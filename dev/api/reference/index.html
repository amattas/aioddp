aioddp¶

aioddp: asyncio DDP sender, color pipeline, and effects for LED pixel controllers.

aioddp.cli¶

aioddp command line: bench tool for a DDP controller with no Home Assistant in the loop.

A thin shell over the library: every command resolves to a Strip, an optional Segment, and one or two library calls inside asyncio.run. Needs the [cli] extra; import aioddp never imports this module.

CLI_BRIGHTNESS_CAP¶

the bench user is standing next to the lights; hass-ddp defaults to 0.6

aioddp.protocol¶

Pure and synchronous; no sockets and no color math.

aioddp.discovery¶

Read a controller's output layout from the DDP JSON config query, or parse a config document fetched elsewhere.

The config document follows the DDP spec ({"config": {"ports": [{"port", "ts", "l", "ss"}, ...]}}) plus the optional extensions p (port number), rev, proto, and conv. parse_config also accepts a document the caller fetched by other means, such as a controller's HTTP API. Stdlib only.

fade¶

async def fade(sender: DDPSender,
               segment: Segment,
               start: bytes,
               end: bytes,
               *,
               duration: float,
               fps: int = DEFAULT_FPS,
               brightness: float = 1.0) -> None

Linearly interpolate segment from start to end over duration seconds.

Sends max(1, round(duration * fps)) frames on an anchored schedule, frame i of n at i * duration / n, so the last, exactly end, lands at duration. duration <= 0 sends end once. Cancelling leaves the last sent frame on the wire.

aioddp.effects.base¶

Effect contract, parameter schema, and parameter validation.

An effect turns (length, t, params, seed) into exactly length * 3 canonical RGB bytes. It knows nothing about strips, gamma, or the brightness cap. render receives params that already went through validate_params (defaults merged, values coerced and range-checked).

BaseEffect Objects¶

class BaseEffect()

Convenience base for built-in effects: not static, no cross-param rules.

Subclasses may override check_params to enforce rules spanning several params; validate_params calls it (when present) after per-param coercion. Effects that don't subclass this still satisfy Effect and simply get no cross-param check.

color_param¶

the param one user-picked color drives; see EffectInfo.color_params

check_params¶

@classmethod
def check_params(cls, params: Mapping[str, Any]) -> None

Raise EffectError naming the offending param when a cross-param rule fails.

validate_params¶

def validate_params(effect: type[Effect],
                    params: Mapping[str, Any] | None) -> dict[str, Any]

Merge defaults, reject unknown keys, coerce and range-check every param.

Strings are accepted for every kind so CLI --param key=value input works: numbers ("1.5", "3"), bools ("true"/"false"), hex or named colors, and comma-separated color lists. Colors normalize to RGB tuples; RGBW is rejected. Raises EffectError naming the param on any failure.
